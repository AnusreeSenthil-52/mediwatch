HOW IT WORKS

From virtual sensor to visible event

The simulator uses generated patient and sensor data; the pipeline is intended to make the software flow inspectable.

Configure a ward

Choose beds, sensors, actuators, scenarios, and a monitoring mode.

Generate readings

Virtual sensor processes publish synthetic measurements to MQTT.

Score & respond

Rules and trend-based look-ahead process readings and produce simulated events.

Review the run

Follow live status, inspect events, then use saved analytics and comparison views.

QUICK USER GUIDE

What the main controls do

Start the local services before opening the simulator. The ward builder contains tabs and controls for the tasks below.

01
SetupAdd or select beds; choose configured sensors and actuators; set patient details and a scenario.
02
Validate · SaveCheck the ward setup and save configuration before starting a run.
03
Start SimulationPick Reactive or Predictive mode in the setup panel, then start the virtual ward run.
04
Run & monitorWatch live vital values and events, review run summaries, and compare the two modes when stopped.
05
Sensor faultsWhile running, choose a bed, configured sensor, fault type, and simulated duration; restore it when done.
06
Manual readings · Trigger collapseChoose a bed and apply synthetic values or inject the configured collapse event for a controlled demonstration.
07
Stop SimulationGracefully stop the virtual ward and save collected readings and events to the local simulation database.
08
Other pagesThe app also provides /dashboard for the monitoring dashboard, /manual for the Patient Lab, and /studio for the technical canvas.
